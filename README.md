# ManualDock

把在线手册、API（Application Programming Interface，应用程序编程接口）说明和 CLI（Command-Line Interface，命令行界面）文档保存到本机。ManualDock 是本地 Chrome 扩展，不需要服务器、云账号或模型接口。

**当前维护版本：0.3.7。** 接手先读 [当前状态与未关闭问题](docs/project-status.md) → [维护边界](AGENTS.md) → [模块与调用路径](docs/architecture.md)。完整文件归属和测试在 [模块清单](docs/modules.json)，可用 `npm run check:handoff` 检查是否漂移。

## 一个工作台，接收多个页面

1. 在 Chrome 的 `chrome://extensions` 开启开发者模式，加载本仓库的 **extension** 目录。
2. 打开 ManualDock，默认进入最左侧的“菜单轮换”。在相应栏目顶部粘贴完整 HTTP/HTTPS 页面 URL，点击“连接管理页”或“连接文档页”，按浏览器提示允许对应网站。
3. 已打开的相同地址会复用；尚未打开的地址会在新标签页加载。管理页进入“菜单轮换”，文档页进入“识别与校准”。连接只登记页面，不扫描目录、不创建采集任务，也不自动开始轮换。
4. 继续逐个粘贴其他页面 URL，顶部列表按当前栏目只显示轮换管理页或文档来源。也可在目标页点击扩展图标，将它加入同一工作台。`adocs.php`、`cdocs.php` 自动归入文档采集，`framework.php` 自动归入菜单轮换；其他地址按当前栏目连接：菜单轮换连接管理页，采集工作台或识别与校准连接文档页。当前栏目不会改变这些已知入口的用途。
5. 在“菜单轮换”识别、试运行和开始菜单操作；文档在“采集工作台”管理，在“识别与校准”检查。切换栏目不停止已启动的轮换。最多管理 8 个来源，可分别采集和暂停。

例如先连接设备管理首页，核对菜单轮换，再连接接口手册和命令手册。两份手册只有在明确点击采集后才运行，某一来源断网或需要登录时不影响另一份任务。保留源标签页；刷新或关闭工作台不停止后台采集和轮换，重新打开后接回原任务。

Windows Chrome 可加载同一份 `extension/`，不需要安装 Python 或 Node.js；本仓库尚未在 Windows 实测。安装、升级与 Edge 兼容性限制见 [维护边界](AGENTS.md#浏览器系统与更新)。

## 识别、保存与恢复

- **快速识别**先读取已经加载的目录；未展开分支、虚拟列表和扫描上限会显示提示。扫描时仍可连接、查看和采集其他来源。在“识别与校准 → 识别设置”检查结果，必要时手动校准。
- **自动识别与手动校准**直接面向当前文档，不再要求选择历史配置。已绑定任务保留自己的范围和进度。续采先核对目录与正文位置；失效位置仅在完整旧队列的章节身份及两个样例正文验证通过后更新，保留任务编号和已保存内容。歧义或章节不一致时停止并提示校准，不选择第一个候选。无法唯一确认旧任务时，显式重新识别仍可建立新任务并保留旧存档。
- **记录当前章**先确认当前选中的目录项与正文，再逐章落盘。整本采集首次验证两个不同章节；同一规则续采复用已完成的验证。
- **失败处理**在采集按钮下方显示停止原因、失败与待核对章数。再次继续时，先检查任务级故障的来源页，恢复失败不消耗下一章，成功后重试被中断且尚未保存的章节。重复正文会保留为待核对，不会因此停止其他章节。章节局部失败不再因连续三章失败而终止全部队列；网络、登录、权限或存储问题会停止该来源。短暂故障按 5、15、30、60 秒逐步重试，上限 3 分钟；重新保存章节后恢复快速重试。登录失效保留 3 分钟等待，不自动登录。手动暂停取消恢复。
- **资料库**支持搜索、类型筛选、分页、查看、导出和删除。运行中的任务必须先暂停再删除，旧控制状态不能把已删除任务写回来。
- **档案恢复**在“已保存”导入此前导出的完整 JSON。只补齐本机缺失的正文；冲突保留本机内容，不自动开始采集。同步指同一扩展安装内的本地任务更新，不是跨设备云同步。

界面固定在窗口内，操作区和长列表不需要上下翻页；正文与诊断预览可以内部滚动。JSON/YAML 格式的 Swagger / OpenAPI 规范在“规范文件”导入。导出包括 Markdown、带已保存图片的离线 HTML、完整 JSON 和采集报告。

旧档案若只剩“请求样例／返回样例”标题，升级不会自动补回正文。暂停后点“重试问题项”，确认补采已知的样例缺失章节；失败时保留原文。只要阅读单文件，可选择离线 HTML；需要迁移或恢复任务则保留 JSON。

## 仓库结构与接手入口

接手维护时，先读 [维护边界](AGENTS.md) 和本节，再读 [开发文档的文件职责与问题索引](docs/development.md#接手阅读顺序)，最后按具体问题查看源码和对应测试。[贡献约定](CONTRIBUTING.md) 规定修改范围和交付要求，[功能状态](docs/function-status.md) 与 [验证记录](docs/validation.md) 用于区分已实现、已验证和仍待现场验收的内容。历史测试结果不代表当前代码已经复验。

```text
manualDock/
├── README.md                 项目入口、安装概览、结构导航、版本日志
├── 使用说明.md               用户操作与导出、恢复说明
├── AGENTS.md                 维护边界、采集限制、Windows 条件与验证要求
├── CONTRIBUTING.md           开发及 AI 接手约定：最小修改、回归、交付边界
├── extension/                Chrome 实际加载的运行源码；优先修改这里
│   ├── manifest.json         版本、权限、后台入口
│   ├── background*.js        单工作台交接、后台来源与任务管理
│   ├── panel.html           控制页结构
│   ├── panel.css            控制页样式
│   ├── panel.js             控制页交互、校准与预览
│   ├── source-*.js、batch.js  页面连接、已有标签复用、来源列表与退出
│   ├── session.js、engine.js 单来源状态与逐章采集
│   ├── 其余 *.js             目录识别、正文读取、存储、恢复、轮换、导入导出
│   └── vendor/               打包后的 YAML 解析库及许可证
├── tests/                    单元、集成和本地浏览器回归；不是产品源码
├── scripts/                  语法检查、镜像同步、依赖打包、发布与公开导出脚本
├── docs/                     开发职责、功能边界、历史验证记录
├── ci/check.yml              持续集成检查模板；当前不在自动执行目录中
├── skill/import-security-manuals/
│   ├── SKILL.md、references/ 可选的 AI 使用指南
│   ├── agents/openai.yaml    技能显示信息和默认提示词
│   ├── scripts/              读取已导出档案的 Python 工具
│   └── assets/extension/     extension/ 的生成镜像，不是第二套独立源码
├── package.json / package-lock.json  开发命令、依赖与锁定版本
└── .editorconfig / .prettier* / .gitignore  编辑格式和忽略规则
```

本机还可能存在 `node_modules/`（开发依赖）、`internal/`（日志、临时测试资料）、`docs/` 下的生成报告和截图、`.git/`（版本历史）、`.workbuddy/memory/`（已有工具历史记录）及 `.DS_Store`（系统文件）。它们不是另一个运行入口，也不是让后续 AI 自动清理、重建或打包的清单。扩展采集的正文存放在浏览器的 IndexedDB 数据库中，由 `extension/task-store.js` 管理，不存放在项目的 `internal/` 中。

**维护时只改所报告问题必需的文件。** `extension/` 是运行源码的维护入口；配套镜像由同步脚本生成，不能两边分别修改。例如“连接文档页重复开页”应沿 `source-controls.js → source-connector.js → batch.js → background-runtime.js` 检查，而不是顺手改目录识别或轮换算法。完整的[逐文件职责表](docs/development.md#运行文件逐项索引)和[问题与测试对应表](docs/development.md#按问题选择源码与回归)在开发文档中。

## 边界

工具只操作用户连接的页面。目标页扩展按钮使用 `activeTab` 临时授权；粘贴 URL 时通过可选网站权限申请所填写的网站，不在安装时要求全站访问。Chrome 的网站授权覆盖该协议与主机，而非单条路径；只有明确连接的标签页才进入控制列表。程序不执行手册里的接口或命令，不自动登录，也不保证设备会话续期。已发现目录全部处理完不等于整册无遗漏；未加载分支、跨域框架、封闭组件和虚拟目录可能需要人工核对。

更新时保持扩展安装路径不变，并在扩展管理页重新加载。更换安装路径可能得到另一套扩展身份与存储。配套 [Skill](skill/import-security-manuals/SKILL.md) 是可选资产，安装 Skill 不会自动安装扩展。
